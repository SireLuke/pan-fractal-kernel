# Gosset 4_21 Geometry Contract for PAN V8

**Status:** Experimental geometry foundation. This document defines the intended primary 8D geometric object; it does not claim a new physical theory.

## Canonical target

The intended polytope is the **Gosset 4_21 polytope**, the 8-dimensional semiregular polytope whose 240 vertices are the roots of the E8 root system. It is not interchangeable with the 8D hyperoctahedron/cross-polytope.

Use the standard E8 root normalization with squared root length 2. The 240 roots are:

1. The 112 permutations of `(±1, ±1, 0, 0, 0, 0, 0, 0)), including all sign choices.
2. The 128 vectors `(±1/2, …, ±1/2)` with an even number of minus signs.

Canonical invariants:

| Invariant | Expected value |
|---|---:|
| Dimension | 8 |
| Vertices / E8 roots | 240 |
| Squared norm of every root | 2 |
| Nearest neighbors per vertex | 56 |
| Edges | 6,720 |
| Inner products against a fixed root | -2, -1, 0, 1, 2 |
| Inner-product multiplicities | 1, 56, 126, 56, 1 |

Two vertices are adjacent in the Gosset 1-skeleton exactly when their root inner product is 1 (equivalently, their squared Euclidean distance is 2).

## Weyl symmetry

For any E8 root alpha, alpha·alpha=2 and the corresponding reflection is:

`s_alpha(x) = x - (x·alpha) alpha`.

The reflection must preserve the complete 240-root set and be an involution. Tests should cover all root lengths, representative reflections, antipodal pairing, and adjacency degree. The Weyl group is generated by these root reflections; a single successful reflection test is not a proof of every group-level property, so broader property-based tests remain desirable.

## Relationship to the old cross-polytope scaffold

The 8D cross-polytope has only 16 vertices (±e_i). It remains useful as a comparison geometry and may appear in selected projection/facet analyses, but it is **not** the primary PAN V8 domain and must not be used as a substitute for the 240-root Gosset vertex set.

Existing V8 coordinate order remains unchanged:

`V8 = (h, R, u, d, tau, chi, s, f)`.

The five UHFE heads, five UDFE inverse heads, paired semantic records, and independent eight-channel projections remain semantic layers over this domain. Do not reinterpret the eight V8 coordinates as the eight signs/orthants, and do not mutate canonical semantic records merely to support geometric rendering.

## Boundary computation

The Gosset polytope is `P = conv(E8_ROOTS)`. Its support function is:

`h_P(u) = max_{v in E8_ROOTS} u·v`.

The radial boundary in unit direction u is not the old cross-polytope L1 formula. The reference implementation computes it by a convex-combination linear program:

- maximize t,
- subject to sum(lambda_i)=1,
- sum(lambda_i * root_i)=t*u,
- lambda_i >= 0 and t >= 0.

This is exact as a convex-hull characterization up to numerical LP tolerances. The optional radial solver requires NumPy and SciPy. Do not run thousands of independent LPs inside JOBF's hot loop; a production renderer should precompute/cache directions, use facet inequalities, or use a validated acceleration structure.

## PAN V8 integration boundaries

- Keep `V8State`, `janus_hydra.py`, and `hydra_semantic_reader.py` interfaces stable.
- Keep UHFE and UDFE as independent semantic fields; do not impose a global complement relation.
- Treat geometry-to-V8 mappings as explicit, versioned transforms with provenance.
- Keep the existing cross-polytope functions as a named baseline/comparison implementation until a separate migration is validated.
- JOBF integration must consume a geometry adapter rather than hard-code `sum(abs(q_i))` as the universal boundary.
- Any 3D/4D rendering is a projection of the 8D Gosset geometry, not a claim that the 8D object is literally embedded in physical 3D space.

## Validation

Run:

```bash
python -m pytest -q tests/test_gosset_421.py
```

The tests validate root construction, uniqueness, norms, antipodes, inner-product multiplicities, vertex degree, edge count, Weyl reflection invariance, reflection involution, support-function behavior, and (when SciPy is installed) LP radial-boundary examples.

Passing these tests validates this software geometry contract. It does not establish a physical interpretation or prove that the PAN semantic variables correspond to E8 roots.
